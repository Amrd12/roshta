# Implementation Plan and Walkthrough: Prescription Printing Automation

Companion to the main spec ([project_documentation.md](file:///d:/all/pro/ps%20plugin/roshta/project_documentation.md)). This file covers how the system is built: division of labor, API and security contracts, the end-to-end execution walkthrough, build phases (server-first), technical Photoshop execution guidelines, and resolved operational specifications.

---

## 1. Assumptions and Architectural Decisions

* **Two Components:** A Python/Flask service packaged as a headless, standalone `.exe` (no Python or Node install required on shop machines) and an Adobe Photoshop UXP plugin that hosts all operator UI.
* **Transport & Communication:** Plain HTTP on `127.0.0.1` with a shared `X-Token` header. The plugin always initiates polling and requests; the server never pushes.
* **Service Lifecycle:** UXP's `launchProcess` API is restricted/unsupported across many Photoshop versions. Therefore, **Windows Startup / Task Scheduler or a desktop launcher is the primary production deployment** (Fallback A). The service monitors `Photoshop.exe` via `psutil` and shuts down gracefully after Photoshop has been closed for a grace period (30–60s).
* **Token Handshake:** On startup, the service generates (or reads from config) a session token and writes it to a known local handshake file (e.g., `%LOCALAPPDATA%/Roshta/session.token` or shared config) so the plugin can authenticate automatically without manual operator entry.
* **Source Folder Convention:** `<Clinic>/<PaperWeight>/<Doctor>.psd`, or `<Clinic>/<Doctor>.psd` when the paper is standard. A missing paper weight folder defaults to `Paper = Standard`. 
  * Files can have numerical/version suffixes (e.g., `Dr_Smith_01.psd`, `Dr_Smith_02.psd`). The scanner strips the suffix for doctor grouping while preserving the distinct file path.
* **Batch Sizing & Incomplete Batches:** A normal batch is 4 designs from the same clinic and paper weight (4-up imposition on 50x34 cm). If the operator invokes **Force Batch** on an incomplete queue (e.g., 2 or 3 files), the unassigned quadrant slots are rendered as clean white canvas and recorded as `[EMPTY]` in the CSV log.
* **Delivery Address Slip:** Optional (off by default), a separate 1-page PDF generated by the Python service summarizing the batch, clinic, and doctor designs.
* **After-Finishing Action:** Executed by the Python service using a delayed, cancelable Windows command (`shutdown`, `rundll32`, etc.). State is fully flushed before any power command fires.

## 2. Responsibilities

### 2.1 Server (Flask exe): The Orchestrator
* Configuration management, rotating file logs, single-instance mutex guard, and token generation.
* Folder scanning with **two-tier file stability check**: size invariance across polling cycles **plus** exclusive read/append file lock check (`open(path, 'r+b')`) to protect against active SMB/network copies.
* Path parsing: clinic, paper weight, and doctor name normalization.
* Plan tree calculation: grouping, planned provisional batches, slot assignment (TL, TR, BL, BR), and output naming.
* Operator selection management (skipped files/folders) with revision tracking (`rev`) and stale-edit rejection (HTTP 409).
* Queue state machine (`session_state.json`) with atomic writes (write temp -> flush -> rename).
* Job leasing: issuing one batch at a time with lease timeouts (default 10 minutes) and idempotent re-delivery.
* Verification on completion: checking TIFF outputs via `tifffile`/Pillow (dimensions, DPI, file integrity), atomic rename from temp to final names, moving source PSDs to `Finished`, appending CSV logs, and copying outputs to RIP hot folders.
* Optional address slip (PDF) generation.
* After-Finishing safety checks and execution.
* Watching `Photoshop.exe` and shutting down after the grace period.

### 2.2 Plugin (Photoshop UXP): The Stateless Worker
* Three-panel React UI: configuration & run controls, live holding queue tree, and activity log drawer.
* Polling `/state?rev=N` to keep UI in sync without unnecessary payloads.
* Run loop: while running, requests `/next-job`, executes the montage, and posts `/job-result`.
* **Photoshop execution:**
  * Master canvas creation: 50x34 cm at 300 DPI CMYK.
  * Quadrant placement: **Place Embedded (Smart Object)** via BatchPlay (bypassing missing font and missing color profile dialogs).
  * Tracker watermark rendering (clinic + batch number) on the `_TRACKER.tif` output.
  * Exporting two temp TIFFs (`_PRINT.tmp.tif`, `_TRACKER.tmp.tif`) with LZW/ZIP compression.
  * Closing documents without saving and invoking memory/cache purge.
* Command entry points: Photoshop Plugins-menu commands for *Pause Queue*, *Resume Queue*, and *Toggle After-Finishing*.
* Countdown modal and resume dialog.

## 3. Core Concepts

### 3.1 Batch States
* `planned`: Provisional batch shown in the tree preview.
* `ready`: 4 designs present, stable, and selected (or fewer if forced).
* `leased`: Dispatched to Photoshop with an active timer lease.
* `verifying`: Photoshop reported success; server is validating TIFF integrity and dimensions.
* `done`: Verified, renamed, sources moved to Finished, and logged to CSV.
* **Failure/Recovery States:** `failed` (plugin error), `interrupted` (lease timed out or crash detected), `flagged` (verification failed; held for operator inspection).

### 3.2 Plan Tree & Revisions
* The server maintains an incremental revision counter `rev`.
* Nodes carry: `id`, `name`, `type` (clinic, paper, file), `status` badge, counts (`[ 2/4 - WAITING ]`, `[ 4/4 - READY ]`), and planned slot allocations.
* The plugin sends the last `rev` it received. If `rev` has changed on the server, the server rejects mutating requests with `409 Conflict` and returns the latest tree.

### 3.3 Selection Rules & Locking
* Operator skips or includes files/folders by checking boxes.
* Skipped nodes do not count toward the wait-for-4 threshold and are left untouched in the source folder.
* Leased or currently processing batches are locked (`423 Locked`). Selection edits only affect unleased batches.
* Exclusion rules persist in `session_state.json` (indexed by path, file size, and mtime).

### 3.4 Batch Numbers
* Provisional batch numbers (`B_PREVIEW_...`) are displayed in the tree preview.
* Final, immutable batch numbers (e.g., `B00142`) are assigned only when `/next-job` transitions a batch to `leased`.
* Counters are stored atomically on disk so numbers are never skipped or duplicated.

### 3.5 Canvas Dimensions, Bleed & Guillotine Tolerances
* **Base 4-up Canvas:** 50x34 cm (two rows of two 25x17 cm prescriptions).
* **Guillotine Tolerance / Bleed Support:** 
  * If source designs are exactly 25x17 cm with zero bleed, edge-to-edge placement is used.
  * The configuration supports an optional **Bleed / Gutter setting** (e.g., 2–4mm gutter between quadrants or 3mm outer canvas expansion to 50.8x34.8 cm with cut tick marks). This prevents blade drag color contamination during commercial trimming.

## 4. API Specification

### 4.1 Common Rules
* Transport: `http://127.0.0.1:<PORT>` (default 49200, configurable fallback).
* Header: Every request must include `X-Token: <SECRET_TOKEN>`.
* Standard error response: `{"error": {"code": "ERROR_CODE", "message": "Human readable description"}}`.
  * `401 Unauthorized`: Missing or invalid token.
  * `404 Not Found`: Unknown job, batch, or file ID.
  * `409 Conflict`: Stale tree revision.
  * `422 Unprocessable`: Invalid configuration or payload.
  * `423 Locked`: Target batch is leased or executing.

### 4.2 Endpoints

| Endpoint | Method | Description |
|---|---|---|
| `/health` | `GET` | Service status, uptime, Photoshop process status, and resume summary (interrupted/in-flight jobs). |
| `/state?rev=N` | `GET` | Returns full plan tree, counters, warnings, disk space, and mode. Returns `304 Not Modified` or empty tree payload if `rev` is unchanged. |
| `/selection` | `POST` | Apply checked/unchecked node changes: `{ "rev": N, "skip": ["id1"], "include": ["id2"] }`. |
| `/next-job` | `GET` | Lease one ready batch. Returns `200` with job JSON, or `204 No Content` if none ready or queue paused/stopped. |
| `/job-heartbeat` | `POST` | Extend active lease timer: `{ "job_id": "...", "lease_id": "..." }`. |
| `/job-result` | `POST` | Report completion: `{ "job_id": "...", "lease_id": "...", "status": "ok"|"error", "outputs": [...], "duration_ms": 12400 }`. |
| `/control` | `POST` | Commands: `play`, `pause`, `stop`, `force_batch`, `retry`, `mark_reviewed`, `set_after_finish`, `cancel_after_finish`, `rescan`. |
| `/settings` | `GET`/`POST` | Read and update configuration (paths, templates, canvas, DPI, bleed). |
| `/feed?after=ID` | `GET` | Retrieve latest chronological activity feed rows. |
| `/csv` | `GET` | Download session or master CSV log file. |

## 5. Photoshop Execution & Engine Guidelines

To guarantee rock-solid stability during unattended runs (avoiding modal dialogs, memory leaks, and font rendering halts), the UXP plugin adheres to the following rules:

### 5.1 Suppress All Modal Dialogs
Before processing any job, Photoshop UI interaction must be disabled:
```javascript
const app = require("photoshop").app;
app.displayDialogs = "no"; // Suppresses missing profile & missing font dialogs
```

### 5.2 Place Embedded (Smart Object) via BatchPlay
Instead of opening each PSD in a separate document window:
* Create the master canvas document (`width: 50cm, height: 34cm, resolution: 300, mode: CMYK`).
* For each input file, execute a BatchPlay `placeEvent`:
  * Embeds the PSD as a Smart Object.
  * Photoshop automatically renders the rasterized composite cached inside the PSD without needing the doctor's custom fonts to be installed on the machine.
  * Translates the layer to the assigned quadrant coordinate (`x_cm`, `y_cm`).

### 5.3 Memory Leak Mitigation
When processing 100+ large batches in an overnight run, Photoshop RAM and scratch disk usage will balloon unless cleaned up:
* After exporting TIFFs, immediately call:
  ```javascript
  await doc.closeWithoutSaving();
  ```
* Every 5 completed batches, execute a memory purge via BatchPlay / DOM:
  ```javascript
  await app.purge("allCaches");
  ```

### 5.4 Exporting Print & Tracker TIFFs
* Export `_PRINT.tmp.tif`: Flatten image, save with TIFF compression (LZW or ZIP), embed color profile.
* Create tracker layer: Add high-contrast diagonal text or perimeter margin text with the clinic name and batch number, set layer opacity to 18%, and export `_TRACKER.tmp.tif`.
* Send `/job-result` to the server with file sizes and duration.

## 6. End-to-End Walkthrough of a Production Run

1. **Service Start:** Operator logs into Windows or launches Roshta. The Python service starts, checks the mutex, verifies port `49200`, writes `session.token`, and begins watching for `Photoshop.exe`.
2. **Plugin Connects:** The operator opens Photoshop. The Roshta panel loads, reads the local token, and calls `/health`. If unfinished or interrupted batches exist from a previous crash, a **Resume Recovery Dialog** appears (`Auto-Restart` or `Flag for Review`).
3. **Scanning & Plan Tree Generation:** The Python background scanner polls source folders. New PSDs pass the file stability check (unchanged file size across 2 polls + exclusive file lock). The server parses clinic, paper weight, and doctor, rebuilds the plan tree, and updates `rev`.
4. **Operator Curation:** The operator reviews the center panel tree. If a doctor's file should be held back, the operator unchecks it. The plugin sends `/selection`, and the server recalculates ready batches.
5. **Start Queue:** The operator clicks **Play** (or uses `Plugins > Roshta > Resume Queue`). Mode transitions to `running`.
6. **Lease Loop:**
   * The plugin calls `/next-job`.
   * The server assigns the permanent batch number (e.g., `B00142`), marks the batch `leased`, saves state atomically to `session_state.json`, and returns the job contract.
   * Photoshop creates the 50x34 cm canvas, places the 4 PSDs via Smart Objects, exports both temp TIFFs, closes the canvas, and posts `/job-result`.
7. **Verification & Finalization:**
   * The Python service verifies that both TIFF files exist, have matching dimensions/DPI, and open cleanly via `tifffile`/Pillow.
   * Atomically renames temp TIFFs to final names: `Al-Amal_Standard_B00142_PRINT.tif` and `_TRACKER.tif`.
   * Moves the 4 source PSDs from `Before acceptance/` to `Finished/<Clinic>/<Date>/`.
   * Appends the batch row to the session CSV and master daily CSV.
   * Copies the print TIFF to the RIP hot folder (if configured).
   * Generates the 1-page PDF delivery slip (if enabled).
   * Marks batch `done`.
8. **Drain & After-Finishing:** When all ready batches are finished:
   * If an After-Finishing action is armed (e.g., *Shut Down*), the UI displays a 60-second cancelable countdown modal.
   * If not canceled and no batches are flagged with errors, the service closes Photoshop, flushes all state, and executes the delayed system shutdown command.

## 7. Failure Handling Matrix

| Situation | Root Cause | Automated Recovery Strategy |
|---|---|---|
| **Plugin reports error** | Corrupt PSD, invalid color mode, disk write error in Photoshop | Batch marked `failed`. Auto-Retry once; if it fails again, mark `flagged` in red, alert operator, and skip to next batch. |
| **Lease expires (10 min)** | Photoshop hung, modal dialog triggered, or crashed | Server reclaims batch, marks it `interrupted`. Server increments retry count. Auto-Restart discards temp TIFFs. |
| **Verification fails** | Corrupt TIFF header, truncated export, or wrong dimensions | Source PSDs are **never moved**. Temp TIFFs kept for inspection. Batch marked `flagged`. |
| **Power cut / Crash** | Sudden machine shutdown mid-batch | On restart, `/health` detects leased/verifying batches in `session_state.json` and presents the resume modal. Counter state is preserved. |
| **Photoshop closed by user** | Operator finished for the day | Python service waits grace period (30–60s) for potential restart, then exits cleanly. State remains safe on disk. |
| **Pause requested mid-batch** | Operator clicks Pause or menu shortcut | Mode becomes `pausing`. The current active batch completes and finalizes cleanly. System enters `paused` state before starting the next batch. |
| **File still copying over SMB** | Prepress operator dropping 150MB PSD | File stability check (size invariance + exclusive read/append lock test) ignores the file until fully released by Windows. |
| **Disk space low (< 5GB)** | Heavy TIFF outputs filling drive | Warning banner in `/state`. Queue automatically pauses and refuses to lease new jobs until disk space is cleared. |

## 10. UXP Spike Checklist & Manifest Requirements

Before writing production React UI, verify these exact UXP capabilities:

   ```json
   "manifestVersion": 4,
   "requiredPermissions": {
     "network": {
       "domains": [
         "http://127.0.0.1:*",

       ]
     },
   ```

3. **BatchPlay Placement:** Confirm BatchPlay `placeEvent` can embed an external PSD file from an absolute Windows path into an active document.
4. **Non-Interactive Execution:** Confirm `app.displayDialogs = "no"` successfully suppresses missing font and missing color profile alerts.
5. **Background Timers:** Verify whether `setInterval` in the panel continues firing when the panel is tabbed behind other Photoshop panels.
6. **Plugins Menu Shortcuts:** Test assigning Windows keyboard shortcuts to the registered plugin menu items (*Pause*, *Resume*).

## 11. Resolved Operational Specifications

* **Doctor Filename Collisions:**
  * Suffixes like `Dr_Smith_01.psd`, `Dr_Smith_02.psd`, or `Dr_Smith-copy.psd` are supported.
  * The scanner regex `r"^(.*?)(?:[_\-\s]\d+)?\.psd$"` extracts the doctor base name for grouping while preserving the distinct file path.
* **Address Slips:**
  * Default: One slip per batch. The slip lists the clinic name, date, batch number, and names of all doctors whose prescriptions are mounted in the batch.
* **Print Specifications:**
  * **Color Mode:** CMYK.
  * **Resolution:** 300 DPI.
  * **Target Profile:** ISO Coated v2 (ECI) or US Web Coated (SWOP) v2 (configurable in settings).
  * **TIFF Compression:** LZW or ZIP (lossless, fast I/O, universally supported by prepress RIPs).
* **Guillotine Tolerance / Bleed:**
  * Default canvas: 50x34 cm (four 25x17 cm quadrants edge-to-edge).
  * Configurable setting: Optional 2–4mm gutter / trim margins for shops with mechanical cutter blade drift.
